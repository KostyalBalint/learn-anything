A container image should be the same artifact in every environment. Everything
that differs between staging and prod lives outside it, in a **ConfigMap**
(plain data) or a **Secret** (data you'd rather not print in a log).

Both are just key/value objects in etcd. The interesting part is how a Pod
consumes them, because the two ways behave very differently.

## Env vars are a snapshot

Environment variables are handed to the process at exec time and that's the end
of it. Edit the ConfigMap afterwards and the running container never notices —
there is no mechanism by which it could. The value is copied.

A **mounted volume** is different: the kubelet syncs the file when the ConfigMap
changes (on its sync period, so seconds to a minute, and never for `subPath`
mounts). Your app still has to *reread* the file — nothing signals it — but at
least the new value is on disk.

So:

- Config that only matters at startup → env vars are fine.
- Config you want to change without a rollout → mount it as a volume **and** watch the file.
- Config you want to change *with* a rollout → env vars, and change the Deployment too.

That last one is the honest default. The trick is to put a hash of the config
into a Pod template annotation, so editing the ConfigMap changes the Pod template,
which creates a new ReplicaSet, which rolls the fleet. Without that, `kubectl apply`
on a ConfigMap changes nothing at all — a silent no-op that looks like a deploy.

## A Secret is not encrypted

A Secret's values are **base64-encoded**, which is an encoding, not a cipher.
Anyone who can `kubectl get secret -o yaml` can read it. What a Secret actually
buys you over a ConfigMap:

- It is not printed by default in `kubectl describe`.
- It can be a separate RBAC subject — you can grant ConfigMap read and deny Secret read.
- The kubelet keeps it in tmpfs rather than on the node's disk.
- It can be encrypted **at rest** in etcd — but only if the cluster operator configured `EncryptionConfiguration`. Off by default in a plain cluster.

Real secret management (rotation, audit, short-lived credentials) means an
external store — Vault, a cloud secret manager, or the Secrets Store CSI driver
projecting them in. The built-in Secret is a delivery mechanism, not a vault.
