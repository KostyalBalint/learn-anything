Every Service gets a DNS name, served by CoreDNS inside the cluster:

```text
<service>.<namespace>.svc.cluster.local
```

Pods are configured with a search path, so from a Pod in namespace `prod`, all
of these resolve to the same ClusterIP:

```text
api                        # relies on the search path
api.prod                   # relies on the search path
api.prod.svc.cluster.local # fully qualified, always works
```

That search path is exactly why `curl api` works from `prod` and fails from
`staging`: the short name resolves relative to the *caller's* namespace. Cross
namespace, you must qualify — `api.prod`.

## Headless Services

Set `clusterIP: None` and you get a **headless** Service: no virtual IP, no
kube-proxy rules. DNS then returns the Pod IPs directly, one A record per ready
Pod. That's what StatefulSets use — each replica also gets its own stable name
(`db-0.db.prod.svc.cluster.local`), which is the point of a StatefulSet: you can
address one specific replica, not "whichever".

Use it when the client needs to see individual members — database replicas,
peer-to-peer clustering, gRPC clients that want to load-balance themselves.
Reach for a normal ClusterIP for everything else.
