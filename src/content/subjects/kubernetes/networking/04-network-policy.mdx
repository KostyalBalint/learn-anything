Default Kubernetes networking: **every Pod can reach every other Pod, in every
namespace.** No firewall, no segmentation. A compromised image-resizing worker
can open a connection straight to the payments database, and nothing in the
cluster objects.

A **NetworkPolicy** is how you take that away. Three rules govern the whole
model, and they're unintuitive in combination:

1. A Pod selected by **no** policy allows all traffic.
2. A Pod selected by **any** policy denies everything in that direction, except what its policies allow.
3. Policies are **additive** allow-lists. There is no deny rule, and no ordering — the union of every matching policy is what's permitted.

Rule 2 is the switch. The moment one policy selects a Pod for `Ingress`, that Pod
is default-deny for ingress and only the listed sources get through.

## Default-deny, then open up

The idiomatic pattern is one policy per namespace that selects everything and
allows nothing:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
spec:
  podSelector: {}        # every Pod in this namespace
  policyTypes: [Ingress, Egress]
```

An empty `podSelector` matches all Pods; no `ingress`/`egress` rules means
nothing is allowed. Then each app ships its own policy allowing exactly its
callers. Because policies are additive, the specific allows layer on top — the
deny-all is never "overridden", there's just nothing to override.

**Do this last, in a namespace you understand.** A default-deny egress rule
blocks DNS, and everything breaks in a way that looks nothing like a network
problem — `curl api` fails to resolve, apps report timeouts, and the policy is
the last place anyone looks. Allow UDP/53 to kube-dns before you turn egress on:

```yaml
egress:
  - to:
      - namespaceSelector:
          matchLabels: { kubernetes.io/metadata.name: kube-system }
        podSelector:
          matchLabels: { k8s-app: kube-dns }
    ports:
      - { protocol: UDP, port: 53 }
```

## Selecting the other end

Three peer types, and the difference between two of them is a classic mistake:

- **`podSelector`** — Pods in *this policy's own namespace*.
- **`namespaceSelector`** — Pods in namespaces matching the label. On its own, **all** Pods in those namespaces.
- **`ipBlock`** — CIDRs, for anything outside the cluster.

Put `namespaceSelector` and `podSelector` in **one list item** and it means "Pods
with this label, in namespaces with that label" — an AND. Put them in **two list
items** and it means "any Pod in those namespaces, OR any Pod with that label
here" — an OR, and a much wider hole than you meant to open. The YAML difference
is a single `-`.

## It needs a CNI that implements it

Like Ingress, the object is inert on its own. The API server accepts a
NetworkPolicy in any cluster; only a CNI plugin that implements policy (Calico,
Cilium, Antrea…) enforces it. On flannel, your policies apply cleanly, report
no errors, and block nothing at all. Verify with an actual connection test, never
by reading `kubectl get netpol`.
